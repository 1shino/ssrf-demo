SSRF服务器端请求伪造攻击

攻击原理

SSRF（Server-Side Request Forgery，服务器端请求伪造，CWE-918）的本质是信任边界被跨越： 外部攻击者无法直接访问的内网（RFC 1918 私有地址段、本机回环 127.0.0.0/8、云元数据端点 169.254.169.254 等），服务器却可以访问。当应用提供一个"代为请求用户给定 URL"的功能 （如网页预览、远程图片加载、Webhook 回调、PDF 渲染、URL 抓取），且未对目标做严格校验时， 服务器就充当了一个被混淆的代理（confused deputy），用自己的网络权限去访问攻击者指定的资源。

1. 根因：信任边界与代请求函数

一个正常的"URL 预览"功能请求流如下，漏洞出现在校验与连接之间的信任假设：

用户输入 url ──▶ [应用解析 url] ──▶ [安全校验?] ──▶ [HTTP客户端发起请求] ──▶ 目标
                         ▲                    ▲                          │
                         │ 信任"用户给的URL"   │ 若仅校验字符串而未限制     │ 服务器以自身权限发起
                         └────────────────────┘ 协议/地址/重定向           ▼
                                                                  可达内网、本机文件、元数据

关键点：校验必须覆盖最终真正发起请求的那一跳，而不是只看输入字符串。许多漏洞恰恰来自 "校验了 URL 字符串、但实际请求被重定向/重新解析到了内网"的时序错配。

2. 协议滥用：file:// / dict:// / gopher://

当底层 HTTP 客户端支持多协议 scheme 时，攻击面从"HTTP 请求"扩大为"任意协议的本地/原始网络操作"：

  • file://（RFC 8089）：不产生任何网络流量，由本地文件系统直接读取，权限等同服务器进程。 file:///etc/passwd、file:///proc/self/environ 即可泄露系统用户与进程环境变量（含密钥）。
  • dict://（RFC 2229 字典协议）：客户端将 URL path 按冒号分割拼成命令行、以 CRLF 结尾并自动追加 QUIT。 可向监听 TCP 的行协议服务灌入命令，如 dict://127.0.0.1:6379/config:get:dir → 实际发送 config get dir\r\nquit\r\n。 局限：冒号分隔与空格分隔的语义冲突，使其难以传含空格/冒号的参数。
  • gopher://（RFC 1436）：URL 中第一个字符为 gopher 类型符，其后的字节经 URL 解码后逐字节原样写入 TCP 连接。 这意味着攻击者可向任意 TCP 服务发送任意原始字节流——这是 SSRF 危害最大的能力，因为它能驱动二进制协议。

3. 真实 Redis RCE 链原理（gopher 驱动 RESP）

Redis 使用 RESP（REdis Serialization Protocol）通信，客户端发送形如 *N\r\n$len\r\n<data>\r\n 的多块数组。gopher 可把一整串 RESP 命令逐字节灌给 Redis， 利用 CONFIG SET 改变落盘路径与文件名、再用 SAVE 触发 RDB 落盘，实现任意路径文件写入：

FLUSHALL                                  # 清空，避免无关数据污染落盘文件
SET  webshell.php  <?php system($_GET['cmd']);?>   # 将攻击载荷作为某个键的值存入
CONFIG SET dir        /var/www/html      # 指定 RDB 落盘目录（Web 根）
CONFIG SET dbfilename shell.php          # 指定落盘文件名
SAVE                                      # 触发 BGSAVE/SAVE，把数据集写入该文件

RDB 文件以二进制格式存储键值，而字符串值原文嵌入其中——故写入的文件会包含攻击者植入的 PHP 载荷， 落在 Web 根即可被解释执行，完成 SSRF → 任意文件写 → RCE 的链路。本演示用真实 RESP 服务(6379)还原了这条链 （载荷用 benign 字符串以避免触发杀软特征码，但落盘机制完全一致）。

4. 内网探测与端口扫描（响应即预言机）

对 http://127.0.0.1:<port> 逐端口请求，依据响应差异即可推断内网拓扑， 即使应用不回显响应体（盲 SSRF）也成立：

  • 连接状态：立即拒绝(端口关闭) vs 超时(被过滤) vs 返回数据(开放) → 区分端口三类状态。
  • 响应时长：开放端口通常快速返回或快速抛协议错误，关闭端口立即 ECONNREFUSED——时长差即扫描信号。
  • Banner / 状态码：Redis 在 6379 收到非法 HTTP 会回 -ERR 文本；MySQL 握手包以特定字节开头； Elasticsearch 未授权返回 JSON。这些特征指纹可识别服务类型与版本。

5. 常见绕过手法（为何"黑名单校验"不可靠）

基于字符串黑名单/正则的校验可被多种解析差异绕过，科学上须以"解析后地址"为校验对象：

  • 等价回环表示：localhost、127.0.0.1、127.1、0.0.0.0、 [::1]、0x7f000001(十六进制)、2130706433(十进制整数)、0177.0.0.1(八进制) 均指向本机。
  • 用户信息段混淆：http://evil.com@127.0.0.1 中 @ 前为 userinfo，实际主机是 127.0.0.1。
  • 重定向：外部可控主机返回 302 指向 http://127.0.0.1:6379；若校验仅作用于首跳，第二跳即绕过。
  • DNS 重绑定（TOCTOU）：校验阶段 DNS 解析返回公网 IP 通过检查，实际连接阶段（TTL=0 的第二次解析）返回 127.0.0.1。 这是基于 IP 的运行时校验也难以防范的根本原因，正确缓解是"解析一次、锁定该 IP、连接该 IP、校验 Host/SNI"。
  • 协议嵌套与解析器分歧：不同库对 file:///etc/passwd、file://etc/passwd、 URL 截断等解析不一致，导致校验器与请求器看到不同目标。

6. 攻击条件（精确化）

  • 应用存在代请求入口（URL 预览/抓取/Webhook/PDF 渲染/SSO 回调等）；
  • 校验未覆盖最终连接（仅校验输入字符串、未限制协议、未处理重定向与 DNS 重绑定）；
  • 服务器进程的网络可达域大于外部用户的可达域（这是 SSRF 区别于普通 CSRF 的关键）；
  • 底层客户端支持 file/dict/gopher 等非 HTTP scheme 时，危害升级为文件读与原始 TCP 注入。

7. 危害与影响

  • 敏感文件读取：/etc/passwd、应用配置、源码、~/.ssh/id_rsa，泄露凭据与密钥。
  • 内网横向探测：枚举存活主机、开放端口、服务指纹，绘制内网拓扑。
  • 未授权服务攻击：访问无认证的 Redis/Memcached/Elasticsearch/内网 Admin API，窃取或篡改数据。
  • 云元数据窃取：请求 169.254.169.254 获取实例 IAM 临时凭据（AWS/GCP/Azure），实现权限提升与横向移动。
  • 远程代码执行：经 gopher 驱动 Redis/FASTCGI 等协议写文件或执行命令，SSRF 直接升级为 RCE。

8. 科学评估：为何难根除

SSRF 之所以长期位列 OWASP Top 10，根因在于校验与连接是两个分离的、存在时序窗口的动作： 只要二者之间存在任何重新解析（重定向、再次 DNS 查询、协议归一化），就存在被构造的输入在两步之间"变身"为内网目标的可能。 因此可信缓解必须是正向的：协议白名单（仅 http/https）+ 目标 IP 白名单（解析后比对，非字符串）+ 禁用重定向或对每一跳重校验 + 解析一次锁定 IP + 移除多余 scheme 支持。下方"防御方法"页给出具体实现。

# 危险的URL预览功能 - 存在SSRF漏洞
@app.route('/preview')
def preview_url():
    url = request.args.get('url')

    # 危险：直接使用用户提供的URL发起请求
    # 没有验证URL是否为内网地址
    # 没有限制可访问的协议
    response = requests.get(url)

    return response.text

# 攻击者可以构造以下请求：
# /preview?url=http://127.0.0.1:6379/     -> 访问内网Redis
# /preview?url=file:///etc/passwd          -> 读取本地文件
# /preview?url=http://192.168.1.1/admin    -> 访问内网管理界面
